# 独立悬浮入口与内置图标提案

日期：2026-09-17。状态：用户已同意，代码已实现；本文件保留提案上下文与实施结果，不代表已发布版本，实际交互以 UX-CONTRACT.md 为准。

## 目标

主界面、悬浮入口和 AI 对话可以分别显示和隐藏。悬浮入口不再要求主界面先折叠。第一版仍是轻量入口，不新增迷你任务列表或桌宠系统。

## 已实现的交互

| 操作 | 结果 |
| --- | --- |
| 首次手动启动 | 打开主界面，同时显示默认圆环；不强制选择外观；AI 不自动弹出 |
| 从悬浮入口打开待办 | 显示并聚焦已有主窗口，保留悬浮入口 |
| 隐藏主界面 | 只隐藏主界面；悬浮入口和已打开的 AI 对话保持原状态 |
| 从任一入口打开 AI | 复用同一个 AI 窗口；首次或隐藏后打开时定位到该入口附近 |
| AI 已打开时再次调用 | 聚焦现有对话；不因切换入口强制移动窗口 |
| 隐藏 AI 的来源窗口 | 对话保持当前位置；不再跟随已经隐藏的来源 |
| 移动 AI 的来源窗口 | 仅跟随本次打开时的原始来源，且来源必须可见；手动移动 AI 后停止跟随，隐藏后重新打开才重新定位 |
| 拖动悬浮入口 | 只更新其独立位置；保留屏幕边界约束和拖动结束后的快捷菜单 |
| 主界面置顶 | 只改变主界面置顶 |
| 悬浮入口置顶 | 只改变悬浮入口置顶；新用户默认置顶 |
| 关闭悬浮入口开关 | 只隐藏悬浮入口；托盘和设置均能重新打开 |
| 托盘单击 / Ctrl + Shift + Space | 只切换主界面显示；不再按“任一窗口可见”隐藏全部窗口 |
| 托盘退出 | 退出整个应用，停止提醒 |

主界面左上角 Logo 恢复品牌展示，移除“收起为图标”操作和变形动画。标题栏现有隐藏按钮改为准确表达“隐藏主界面”。悬浮菜单保留“打开待办”“AI 对话”“置顶图标”，不用“展开”描述窗口行为。

正常启动恢复主界面上次显隐和悬浮入口开关；登录自启动的 `--hidden` 抑制主界面，不覆盖其手动启动偏好，按悬浮入口开关显示图标。AI 重启后不自动打开。上述启动默认值已接入。

## 原批准代码范围（已落实）

1. `electron/main.ts`：复用现有 `dockWin`。用独立显隐替代 `presentDock` / `presentMain` 的互斥切换；拆开 `hideMain`、托盘、全局快捷键、置顶以及退出行为。悬浮入口的 hover 和 drag 不再依赖 `compact`。主界面操作不再覆盖 `dockPosition`。
2. `electron/main.ts`、`shared/contracts.ts`、`electron/preload.ts`：明确主窗、悬浮入口的动作与状态；AI 打开请求携带来源 `main` / `dock` / `tray`。气泡使用来源所在显示器的工作区，不能继续固定按主窗口所在显示器定位。用户已拖动的对话不被后台事件拉回。
3. `src/App.tsx`、`src/styles.css`：移除主窗折叠/展开动画和 `compact` 联动；保留现有悬浮外形、可拖动行为、键盘菜单与减少动态效果支持。图标单击行为先保持现状，不额外引入单击/双击约定。
4. `src/SettingsPanel.tsx`：将“折叠图标”改为“悬浮入口”，添加启用开关、四款内置外观选择，保留上传和恢复已上传图片。不要新增顶层设置页签或强制初始化向导。
5. 图标采用固定内置 ID：`orbit`、`note`、`sprout`、`cat`。通过共享的图标渲染入口供悬浮窗和设置预览使用。现有品牌 Logo 与应用/任务栏/托盘图标继续各自使用原资产。
6. 实现完成后同步 `DESIGN.md`、`UX-CONTRACT.md`、`PRODUCT.md`、相关 README 与桌面回归脚本；以最终行为更新，不把本提案当作已经发布的合同。

## 设置兼容

- 沿用现有设置键值存储，不增加业务数据表。已新增 `dockEnabled`、`mainVisible`、`dockAlwaysOnTop`、`dockIconPreset`；AI 会话持久化保持现状。
- 首次迁移只在新设置不存在时读取旧 `compact`：旧折叠状态对应主界面隐藏、悬浮入口开启；旧展开状态保留主界面显示。之后不再用旧值覆盖新选择。
- 保留 `dockPosition`、主界面位置和上传图片文件；内置图标切换不删除上传图片。旧 `dockIconSource=custom` 继续使用用户图标，旧默认映射到 `orbit`。
- 悬浮置顶初值沿用旧置顶设置，新安装默认开启；此后主窗和悬浮入口各自控制。已移除旧主窗置顶对 AI 的批量修改，AI 保持自身窗口行为。

## 图标预览

`preview.png` / `preview.svg` 为四款对照。每款有单独的 72×72 SVG：

- `orbit.svg` 圆环：沿用当前 `BrandMark` 的圆环与红点比例，已作为默认。
- `note.svg` 小笺：便笺与勾选，突出待办用途。
- `sprout.svg` 嫩芽：低饱和绿色，作为温和的外观选项。
- `cat.svg` 团猫：简洁静态猫脸，作为轻松的外观选项。

制作方式：直接编写 SVG，PNG 由本地 Sharp 渲染；未使用生成式图片工具。四款已接入 `public/dock-icons/`，由 `src/DockIcon.tsx` 供悬浮入口和设置预览共用。新增颜色仅属于图标资产，不改变应用主题；切换内置款式保留已上传的自定义图片。

## 实施与验收顺序

1. 先拆窗口关系：验证主界面与悬浮入口同时可见、单独显隐、AI 不被连带关闭、托盘与快捷键不误藏入口。
2. 再接入图标与设置兼容：验证四款切换、上传图保留、重启恢复，以及旧版本默认/自定义图标迁移。
3. 完成桌面验证：覆盖两窗口位置独立记忆、不同显示器上的 AI 定位、屏幕移除后找回窗口、置顶独立、悬浮拖动和键盘菜单。测试使用隔离数据目录。

已改写 `dock-regression.mjs` 中互斥显隐的断言，同时保留“操作图标不得缩放或移动主窗口”的约束。本次实现验证已通过 6 组悬浮入口回归、26 项单元测试及 `npm run test:desktop` 的 14 组 UX 回归（`test-results/ux-current/result.json`）。旧 `tooling/desktop-test.mjs` 仅做语法检查，未执行。显示器场景采用模拟，不替代实机多显示器、屏幕热拔插和登录自启动验收。

完成审查结果为 `ship`，范围仅限悬浮入口设置与预设图标：提交截图有效，无需实质性修正；此结论不代表整个应用或全部 Windows 场景已获验收。文档按既有 UI 与 token 体系补充本次扩展，不另建主题或转换全局文档格式。
